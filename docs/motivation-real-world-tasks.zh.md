# 动机 —— 前沿模型的盲区与训练专才

这个 benchmark 真正为之而建的 framing，以及它对应的现实任务。

## Framing

前沿模型是通才。任何一个任务里，一部分难度是它**擅长**的——能推理的结构、能写的代码、能推断的
规律；另一部分是它**结构性不擅长**的：一个稠密、低结构的映射，没有规律可推，条目又多到塞不进
context。对后一部分，正确的做法不是"更用力地想"或"检索更多"，而是**训一个小专才**把它吃下。

Glyph 把这件事变成一个可测的问题：

> **π ≈ 一个任务里有多少落在前沿模型的盲区。**
> 一个通才 agent 能不能识别这个盲区、决定何时把它委托给一个训出来的专才、并真的让这个专才起
> 作用——以及在 π 多大时这个决定才划算？

### Glyph 怎么编码它

| Glyph 部件 | 现实读法 |
|---|---|
| **tables**（冻结随机 MLP、无规律） | 前沿模型的结构性盲区——一个推不出规律的映射 |
| **skeleton**（可描述的组合） | 前沿模型本就擅长的——当场在 context 里解掉 |
| **π** = skeleton 占难度的份额 | "任务里盲区占多大"的**补集**（低 π = 大半是盲区） |
| **query** 工具 | 对盲区的便宜采样——每问一次，拿到一个 cell |
| **final 阶段**（query 关闭） | 部署期：没有 oracle，只能靠学到的东西回答新输入 |
| **train 臂**（free protocol：容器里有一块 GPU，并在环境描述里被告知） | "识别弱点 → 训一个专才"这个能力本身 |
| **weights ceiling**（reference 侧） | 在给定数据预算下，一个训出来的专才最多能吃下多少盲区 |
| **`unary/binary_coupling`** | 盲区有多**可学/有结构**——"易模态 vs 难模态"的旋钮 |

低 π → 任务大半是盲区 → 训专才该大赚；高 π → 前沿模型本就行 → 训专才是浪费，直接想就好。
benchmark 量的就是：agent 这个 call 做对没有、以及专才到底有没有用。

## 什么样的现实任务是 "Glyph 型" 的

一个任务要能用 Glyph 来建模，得同时满足三点：

1. **有一个能便宜查询、但写不出规则的系统。** 对应 tables 加 query。
2. **任务里还有一部分是能推理出来的结构。** 对应 skeleton。两部分混在一起，agent 自己要分清
   哪部分该推、哪部分该学。
3. **最后要在没有查询的情况下回答新输入。** 对应 final 阶段关掉 query。这一条经常被忽略，但它
   正是"查表"和"学习"的分水岭：能查的时候，记忆就够了；不能查的时候，只有泛化才有用。

下面四类现实任务都满足这三点，但贴合的方式不同。

## 它对应的现实任务 —— "前沿模型不擅长 → 训个专才"

### 1. 特定模态 / 信号

**现实样子。** 一个 agent 拿到一堆原始信号（心电、振动、光谱、显微图像），要做诊断、分类或回归。
前沿模型可以"看图说话"，但在像素或采样点层面的判别能力，远不如一个在该模态上训过的小模型。

**具体应用。**
- 医疗：ECG 心律失常分类、EEG 癫痫发作检测、睡眠分期。
- 工业：轴承振动做预测性维护、产线相机做缺陷检测、遥测数据做异常检测。
- 地球科学：地震波相位拾取、卫星图像做土地利用分类。
- 生物：蛋白功能预测、分子性质预测、显微图像细胞计数。
- 声学：鸟类叫声识别、机器噪声诊断。

**对回 Glyph。** 信号到标签的映射是 table；围绕它的预处理、聚合、报告规则是 skeleton；标注好的
样本是 query；π 对应"这个任务里感知占多大比例"。一个 ECG 报告任务 π 可能很高（大部分是按指南
写报告），而一个纯波形分类任务 π 很低。

**Glyph 能测什么。** agent 面对信号，会不会先试图"用眼睛看、用常识推"，然后在效果不好时转去训
一个分类器？Glyph 里对应的路径是：先找规则 → 找不到就退到统计表或放弃 → 还是转去拟合模型。

**类比的弱点。** Glyph 的输入是符号化的数字三元组，不是连续的高维信号。它测不出"读原始信号"
这个模态上的弱点本身，只能测"意识到该学"这个决策。要把这一类建模得更像，可以考虑一个变体：
把 value 渲染成波形或图像再给 agent。

### 2. 无结构的精确映射（最接近 Glyph 的随机表）

这是和 Glyph 最贴近的一类，几乎一一对应。

**现实样子。** 一个黑箱系统，调用很便宜，输出确定，但内部逻辑写不出来，或者因为历史原因没人
知道。

**具体应用。**
- **遗留业务系统**：保险费率引擎、航空票价计算、税务计算器、几十年前的 COBOL 业务规则。要迁移
  或替换它们，第一步就是搞清楚它到底在算什么。
- **他人的打分和排序函数**：搜索引擎排名、广告竞价、信用评分、推荐系统。做 SEO 或做对手分析的
  人每天都在反推黑箱。
- **模拟器代理模型**：CFD、气候模型、电路仿真、游戏物理引擎。跑一次很贵，希望用一个小网络替代
  （科学计算里的 surrogate modeling）。
- **仪器标定**：传感器的非线性响应曲线、相机的色彩变换。
- **数据集特有的模糊匹配**：某公司内部的实体解析规则、地址归一化逻辑。
- **编译器和优化器的行为**：某个 flag 组合下性能如何，几乎没人能从源码推出来。

**对回 Glyph。** 黑箱本身是 table；API 的调用结构、参数组合方式是 skeleton；调用黑箱是 query；
"用学到的代理模型回答新输入"是 final。π 对应系统里有多少是可读的接口逻辑、多少是不透明的核心。

**Glyph 能测什么。** agent 会不会一直假设黑箱里有一条精确规则，在证据表明没有规则时仍然不放手；
会不会停下来测一次"这东西能不能学"；查询预算怎么花——是做受控实验推结构，还是随机采样喂模型。

**一个有用的对照。** 现实里的黑箱并不都能学：密码学里的 S-box 设计目标就是不可学，一个随机置换
表也学不出来。一个好的 agent 应该能在"有规则可推"、"可学但无规则"、"不可学"三种情况下分别选
推理、学习、放弃。Glyph 目前只覆盖中间一种；替换表的生成方式可以把谱的两端补上。

**类比的弱点。** 真实黑箱通常有部分结构：单调性、分段线性、对某些变量不敏感。coupling 旋钮能调
一部分，但调不出"单调"这类归纳偏置。

### 3. 高吞吐分类 / 抽取（蒸馏专才）

**现实样子。** 一个窄任务要跑几百万次：内容审核、工单路由、意图识别、PII 检测、领域 NER（临床、
法律）、日志异常分类、邮件分流、代码评审初筛。用前沿模型逐条调用既贵又慢，蒸出一个小模型在质量
和成本上都更好。

**对回 Glyph，有一处和前两类不同。** 这里的 oracle 往往是**前沿模型自己**：agent 可以自己标注
样本，然后训一个小模型替代自己。query 对应"调用昂贵的老师"，final 对应"部署后不能再调老师"。
Glyph 的两阶段结构恰好对应"有老师的开发期"和"没老师的部署期"。

**Glyph 能测什么。** 这一类的核心是**经济学决策**：什么时候值得蒸馏？这取决于三个量：调用量、
老师和学生的成本差、学生能达到的质量。Glyph 现在只测第三个。

**类比的弱点，也是扩展方向。** Glyph 里 query 几乎免费，final 阶段也没有推理成本或延迟限制，
所以"蒸馏划不划算"测不出来。要覆盖这一类，需要加两个旋钮：query 的单价（恢复一部分查询成本，
但不是硬上限），以及 final 阶段的回答预算（每题的延迟或算力限制，迫使 agent 不能靠一个巨大的
查表来应付）。加上之后，Glyph 就能问"在什么成本结构下蒸馏才值得"。

### 4. Agent-as-AutoML / 自我改进（最新、最能立住）

**现实样子。** 一个 long-horizon agent，跑着跑着意识到"这个子任务我老做错——我来训个模型"，写训
练代码、微调、评估、再把专才接回去。这个自主 ML 工程的能力几乎没有干净的测试台。

**具体应用。**
- **编码 agent**：学会某个代码库特有的命名约定、某个 CI 的失败模式和原因的映射。
- **科研 agent**（autoresearch、AI Scientist 一类）：为一个昂贵的实验环节训代理模型，用它筛选候选。
- **机器人和具身 agent**：为某个难以建模的动力学部件学一个预测模型。
- **数据工程 agent**：学一个脏数据源到标准 schema 的映射。
- **运维 agent**：学"告警模式 → 根因"的映射。
- **游戏和搜索 agent**：为局面估值训一个价值网络（AlphaGo 式的经典做法）。

**对回 Glyph。** free protocol 就是这一类的最小模型：一个开放的容器、一个只能靠查询了解的系统、
一段有限的时间，然后在没有查询的条件下交答案。正确答案已知（靠天花板），所以能量 agent 的**决定**
对不对、训练到底**有没有**帮上。

**类比的弱点。** Glyph 只有一个候选子任务（binary 表）。真实长程任务里有很多子任务，其中大多数不
值得训练，agent 要在一堆子任务里识别出那个"反复出错且可学"的，难度比 Glyph 高得多。一个可能的
扩展是让 Glyph 同时有几张表，有的能推、有的能学、有的两者都不行。

### 四类的横向比较

| | 1 模态 / 信号 | 2 黑箱映射 | 3 蒸馏 | 4 自我改进 |
|---|---|---|---|---|
| 和 Glyph 的贴合度 | 中 | **高** | 中 | **高** |
| "该不该学"这个决策的分量 | 中 | 高 | 低（更多是经济学） | **最高** |
| Glyph 已经能测的 | 决策 | 决策、查询策略、方法选择 | 学生的质量 | 决策、训练是否奏效 |
| 要补的旋钮 | 非文本输入 | 可学性谱（替换生成器） | 成本结构 | 多子任务 |

2 是最干净的类比，4 是最有时效性的应用；1 和 3 是这个 framing 能覆盖、但需要再加旋钮的延伸。

## 一个曾经的短板 —— 以及它为什么是一根可控的轴，而非死结

在上面的现实案例里，训专才之所以赢，是因为那个模态**有结构**：小模型能从有限数据泛化到没见过的
输入。Glyph 的表是随机 MLP，早先担心它是**最坏情况**：专才只能记住见过的 cell，Glyph 会按字面
**低估**专才在真实结构化模态上的威力。

free protocol 的 run 表明这个担心过头了。表建在共享的逐数字 embedding 上，这给了它可学的结构：
在 `low_3` 上，只看单个数字位的统计表最多拿到约 0.55 的 binary probe，而 agent 自己拟合的 MLP 和
树模型拿到 0.73–0.83——学生确实在泛化，不只是记忆。

有多可学，是由 `unary/binary_coupling` 旋钮控制的：调高，盲区更逐数字可学，专才更容易泛化；
调低，就更接近只能记忆的最坏情况。所以 Glyph 能建模**从难模态（专才只能记）到易模态（专才能泛化）
的整条谱**——这正是决定"训专才值不值"的那根轴，也是你在真实数据上根本拨不动的。

## 这个 framing 对 benchmark 的要求

要在这个 framing 下站得住，benchmark 必须能测两件事：

1. **agent 有没有正确识别盲区、并决定去训一个专才？**（是决策，不只是最终分。）
2. **一个真能泛化的专才在这里可行吗**——这要求 (a) coupling 让盲区可学，(b) 协议给 agent
   **足够的数据和时间，去先训得出一个有用的专才**。

v2 协议的两个 pilot 是警示：agent **确实尝试了训专才**，但被 harness 卡住了（约 50 步梯度、拿不到
干净的 cell 级数据）——不是这个想法错。**如果协议饿死了专才，你就永远量不出委托给专才何时划算**，
而那正是整件事的意义所在。free protocol 因此去掉了查询、提交和轮数的上限，只保留 wall-clock，
让 (b) 成立。

## 一句话定位

> 一个通才 agent，面对一个部分超出自己能力的任务，决定何时训一个专才来补上缺口——而 π 是一个
> 可测的旋钮，用来问"缺口要多大，这个决定才值得"。Glyph 是这个决定的受控测试台；coupling 旋钮
> 让它能横跨"难学"和"易学"两种盲区——而真实数据从不让你这样拨。
