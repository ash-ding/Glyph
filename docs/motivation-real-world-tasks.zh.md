# 动机 —— 前沿模型的盲区与训练专才

这个 benchmark 真正为之而建的 framing，以及它对应的现实任务。

## Framing

前沿模型是通才。任何一个任务里，一部分难度是它**擅长**的——能推理的结构、能写的代码、能推断的
规律；另一部分是它**结构性不擅长**的：一个稠密、低结构的映射，没有规律可推，条目又多到塞不进
context。对后一部分，正确的做法不是"更用力地想"或"检索更多"，而是**训一个小专才**把它吃下。

Glyph 把这件事变成一个可测的问题：

> **π ≈ 一个任务里有多少落在前沿模型的盲区。**
> 一个通才 agent 能不能识别这个盲区、决定何时把它委托给一个训出来的专才、并真的让这个专才起
> 作用——以及在 π 多大时这个决定才划算？

### Glyph 怎么编码它

| Glyph 部件 | 现实读法 |
|---|---|
| **tables**（冻结随机 MLP、无规律） | 前沿模型的结构性盲区——一个推不出规律的映射 |
| **skeleton**（可描述的组合） | 前沿模型本就擅长的——当场在 context 里解掉 |
| **π** = skeleton 占难度的份额 | "任务里盲区占多大"的**补集**（低 π = 大半是盲区） |
| **train 臂**（`build_dataset`/`train`/`student_infer`） | "识别弱点 → 训一个专才"这个能力本身 |
| **weights ceiling** | 在给定数据预算下，一个训出来的专才最多能吃下多少盲区 |
| **`unary/binary_coupling`** | 盲区有多**可学/有结构**——"易模态 vs 难模态"的旋钮 |

低 π → 任务大半是盲区 → 训专才该大赚；高 π → 前沿模型本就行 → 训专才是浪费，直接想就好。
benchmark 量的就是：agent 这个 call 做对没有、以及专才到底有没有用。

## 它对应的现实任务 —— "前沿模型不擅长 → 训个专才"

### 1. 特定模态 / 信号
前沿模型读原始非文本信号很弱；一个在该模态上训过的小模型能赢。
- 原始时序：ECG、EEG、加速度计 / IMU、工业遥测、地震波、频谱图。
- niche 音频/语音；蛋白 / DNA 序列；分子图；点云。
- 领域图像（微调视觉模型胜过通用 VLM）：医学扫描、卫星、显微、工业缺陷检测。

agent 的流程：先自己试（描述、对信号推理）→ 只是一般 → 为该模态训/微调一个小分类器或回归器。

### 2. 无结构的精确映射（最接近 Glyph 的随机表）
一个模型推不出规律、但取样很便宜的映射。
- 黑箱打分 / 排序函数、私有定价模型、标定曲线。
- 没有闭式解的模拟器 input→output。
- 某个数据集特有模式下的模糊匹配 / 实体解析。

模型推不出来；一个在样本上训的小回归器就能拿下。

### 3. 高吞吐分类 / 抽取（蒸馏专才）
在一条窄赛道上，蒸出来的小模型**既比通才准、又在规模上便宜得多**。
- 路由、审核、意图分类、领域 NER / 抽取。

这是盲区 framing 叠加服务经济学：专才在质量（专注窄域）和成本（一次性摊销 vs 按次付费）上都赢。

### 4. Agent-as-AutoML / 自我改进（最新、最能立住）
一个 long-horizon agent，跑着跑着意识到"这个子任务我老做错——我来训个模型"，写训练代码、微调、
评估、再把专才接回去。这个自主 ML 工程的能力几乎没有干净的测试台。Glyph 是一个：正确答案已知
（靠天花板），所以能量 agent 的**决定**对不对、训练到底**有没有**帮上。

## 诚实的短板 —— 以及它为什么是一根可控的轴，而非死结

在上面的现实案例里，训专才之所以赢，是因为那个模态**有结构**：小模型能从有限数据泛化到没见过的
输入。而 Glyph 的表是**随机 MLP——最坏情况**：专才只能记住见过的 cell（外加很弱的逐数字外推），
所以按字面 Glyph **低估**了专才在真实结构化模态上的威力。

但这个差距恰恰是 Glyph 的 `unary/binary_coupling` 旋钮所控制的：把它调高，盲区就变得更逐数字可
学——专才开始泛化而不只是记忆。所以 Glyph 能建模**从难模态（专才只能记）到易模态（专才能泛化）
的整条谱**——这正是决定"训专才值不值"的那根轴，也是你在真实数据上根本拨不动的。

## 这个 framing 对 benchmark 的要求

要在这个 framing 下站得住，benchmark 必须能测两件事：

1. **agent 有没有正确识别盲区、并决定去训一个专才？**（是决策，不只是最终分。）
2. **一个真能泛化的专才在这里可行吗**——这要求 (a) 把 coupling 调起来让盲区可学，(b) 给 train 臂
   **足够的预算，去先训得出一个有用的专才**。

那两个 pilot 就是警示证据：agent **确实尝试了训专才**，但失败了——是被 harness 卡的（约 50 步梯度、
拿不到干净的 cell 级数据），不是这个想法错。见 `open_questions.md` 的"the train arm cannot obtain
enough data to train a usable student"。在这个 framing 下这不是细节——**如果协议饿死了专才，你就
永远量不出委托给专才何时划算**，而那正是整件事的意义所在。

## 一句话定位

> 一个通才 agent，面对一个部分超出自己能力的任务，决定何时训一个专才来补上缺口——而 π 是一个
> 可测的旋钮，用来问"缺口要多大，这个决定才值得"。Glyph 是这个决定的受控测试台；coupling 旋钮
> 让它能横跨"难学"和"易学"两种盲区——而真实数据从不让你这样拨。
